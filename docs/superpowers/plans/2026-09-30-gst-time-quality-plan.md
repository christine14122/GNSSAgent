# GST 时间可信度实施计划

目标：按已确认的 RMS 窗口方案计算时间质量；用户明确无需旧版兼容，直接升级 TCP v2，将时间质量嵌入 SIMPLE/FULL。

1. `internal/timequality`：实现带门限验证、连续窗口、滞回、时间连续性与超时的纯状态机；测试缺失/零/非有限 RMS、重复秒、跨日、跳变、恢复和边界。
2. `internal/config`：配置 RMS 进入/退出/极差、窗口和超限次数、超时与走时容差；拒绝非法组合。主入口传给聚合器，服务启动日志记录参数。
3. `internal/aggregate`：从周期原始语句提取对齐的最大 RMS、日期/小数秒冲突与导航状态；将结果放入内部 FullStatus；保留原 GST 首个有效字段语义。逆序完整 UTC 立即在本地撤销可信状态。
4. `internal/protocol` 和 `internal/server`：帧头 version=2；SIMPLE 64 字节载荷/72 字节帧、FULL 136 字节载荷/144 字节帧；直接编码时间状态、原因、超时，FULL 另有样本数及 bit29 对应的 time_rms。删除独立质量消息与配对队列机制；测试偏移、零值有效性、慢客户端替换、两个订阅类型和旧版本拒绝。
5. `internal/app`：内部定时检查仅清除过期状态；没有新数据不发状态、心跳或独立质量通知。质量随下一新周期输出；用可控时钟验证断流静默、恢复和本地撤销。
6. 同步 v2 协议、现行需求及部署参数；文档要求客户端断连或最后一条新状态的单调接收年龄达到 time_timeout_ms 时停止采用。运行 `go test ./...`、Linux race 测试、协议文档检查与五目标构建。
7. 保留旧 v1.docx 作为历史快照，在 v2 Markdown 中明确它未更新；实机 GST 尚待设备配置，构造输入验证不等于实机标定。

所有测试使用现有 Go testing 与标准库，不新增依赖。实现保留可配置门限，不承诺尚未标定的绝对授时精度。
