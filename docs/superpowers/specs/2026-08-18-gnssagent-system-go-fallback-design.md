# GNSSAgent 系统 Go 选择与回退设计

## 目标

调整 Linux Make 构建的工具链选择：普通目标优先使用系统 Go，失败后使用仓库内置 Go 1.26.4 重试一次；HF 始终使用精确的 Go 1.23.12，并且构建失败后不重试。

本改动只修改 `build/scripts/make/Makefile` 及其行为测试。四个薄封装 Makefile、Windows PowerShell 构建、目标架构、输出名称和清理规则保持不变。

## 普通目标

`test`、`ccu`、`multiband-radio` 和 `multiband-handheld` 使用相同规则：

1. 通过 `command -v go` 检查系统 Go。
2. 系统 Go 存在时，记录 `go version`，并设置 `GOTOOLCHAIN=local` 执行当前命令。系统 Go 不受版本限制。
3. 系统 Go 命令成功时立即结束，不检查、不校验、也不解压 `build/compiler` 中的 Go 1.26.4。
4. 系统 Go 命令失败时，打印回退日志，调用现有 `go126` 工具链准备目标，然后使用内置 Go 1.26.4 将同一命令重试一次。
5. 系统没有 Go 时，跳过首次尝试，直接准备并使用内置 Go 1.26.4。
6. 内置 Go 命令失败时保留其非零退出码并立即报错，不再进行第三次尝试。

`GOTOOLCHAIN=local` 同时用于系统和内置 Go，防止 Go 自行联网切换工具链。系统 Go 的失败可以来自版本不兼容、编译错误、测试错误或其他非零结果；Makefile 不猜测原因，只执行一次约定回退。

每个 Make 目标独立执行该规则。一次 `make build` 中，如果多个目标分别使用系统 Go 失败，它们各自最多回退一次；不创建跨构建持久化的“系统 Go 不可用”标记。

## HF 目标

`hf` 使用严格规则：

1. 检查系统 `go version` 是否精确等于 `go version go1.23.12 linux/amd64`。
2. 精确匹配时直接使用该系统 Go 构建 HF。
3. 系统 Go 不存在、无法运行或版本不匹配时，准备并使用 `build/compiler/go1.23.12.linux-amd64.tar.gz`。
4. 无论选中系统 Go 还是内置 Go，HF 构建只执行一次；失败后立即报错，不切换工具链重试。

HF 继续使用 `CGO_ENABLED=0 GOOS=linux GOARCH=arm GOARM=7` 和 `buildinfo.Target=hf`。

## 实现结构

主 Makefile 内定义两个私有 Make 宏：

- 普通命令宏：接收 Go 子命令及目标环境，执行“系统 Go → 内置 Go 1.26.4”的一次回退。
- HF 命令宏：只负责在精确系统 Go 1.23.12 与内置 Go 1.23.12 之间预先选择，然后执行一次。

继续复用现有 `go126`、`go123` 工具链准备目标及其 SHA-256、`flock`、完成标记和恢复逻辑。准备目标改为按需通过递归 Make 调用；不再作为普通构建目标的无条件前置依赖。

日志至少区分：

- 使用的系统 Go 路径和版本；
- 系统 Go 命令失败并准备回退；
- 系统 Go 缺失而直接使用内置工具链；
- HF 系统版本不匹配而选择内置 Go 1.23.12；
- 内置重试仍失败。

## 错误与完整性

- 系统 Go 成功路径不依赖内置归档存在。
- 需要回退但归档缺失、哈希错误、解压失败或版本错误时，由现有工具链准备逻辑失败关闭。
- 递归 Make 的失败不得被 shell 条件或日志命令掩盖。
- 系统 Go 首次失败不作为最终错误；只有内置重试失败才令普通目标失败。
- HF 第一次实际构建失败就是最终错误。

## 测试

扩展 `tests/make.test.sh`，使用可控的伪系统 Go 和伪内置归档验证：

- 普通目标在系统 Go 成功时不访问缺失的内置归档。
- 普通目标在没有系统 Go 时直接使用内置 Go 1.26.4。
- 普通目标系统 Go 失败后，内置 Go 成功，目标整体成功且两者各执行一次。
- 普通目标系统 Go 和内置 Go 都失败时，目标失败且不执行第三次。
- `test` 遵循同样的一次回退规则。
- HF 精确系统 Go 1.23.12 时只执行系统 Go；即使失败也不执行内置 Go。
- HF 系统 Go 缺失或版本不匹配时只执行内置 Go 1.23.12。
- 系统成功路径不要求 Go 1.26.4/1.23.12 归档存在；回退路径继续覆盖缺失归档与错误哈希。

最终验证继续包括 PowerShell 构建契约、Linux 行为测试、真实默认 Make 构建、四个真实单目标构建和 ELF 架构检查。
